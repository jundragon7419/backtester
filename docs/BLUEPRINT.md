# KRX Backtester 청사진

## 0. 목적과 범위

KRX 일봉 데이터로 **전략을 탐색하고 검증하는 백테스팅 도구**. 특정 전략을 돌리는 것이 아니라, 여러 전략 계열과 파라미터를 시험해 실거래 후보를 골라내는 것이 목적이다.

설계 기준: 어떤 기능이 없을 때 **탐색 결과가 틀리면 1차에 포함**하고, **조금 덜 정밀할 뿐이면 2차 확장 후보**(11장)로 둔다.

| 포함 | 제외 |
|---|---|
| KRX 일봉 수집·정제 | 실거래, 주문 전송 (키움 자동매매 프로젝트 담당) |
| 전략 정의 (이벤트형, 리밸런싱형) | 분봉·틱 데이터 |
| 대량 탐색(1층) + 현실 제약 검증(2층) | 해외 시장 |
| 데이터 스누핑 통제 (조합 단위 기록, OOS screening holdout) | 전진 검증 (키움 모의투자 담당) |
| 통과 전략 파일 출력 | 11장의 2차 확장 항목 |

## 1. 확정된 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 데이터 원천 | KRX Open API 원시 일봉 + 자체 보정. 키당 하루 10,000회(약관 제8조④), D일 데이터는 D+1 영업일 08시 이후 제공 | 공식 원천, 무료. M0에서 기준가 역산 계수(삼성전자 1/50), 부호 있는 `대비`, 폐지 종목의 과거 스냅샷 포함을 실측 확인 |
| 가격 보정 | 필수. 기준가 역산으로 보정 계수 산출, 계수 타당성 검사, 수정주가 제공 라이브러리 교차검증을 완료 조건으로 사용 | 미보정 시 모든 가격 기반 전략 오작동. OpenDART 구조화 API에는 액면분할이 없음 |
| 자본변동 잔고 처리 | 이벤트 분류는 **직전 거래일 정지 여부**를 먼저 보고 분기. 정지 후 재개일에 분할 비율과 상장주식수 변화가 함께 맞으면 `share_change`, 아니면 `restructure`. 정지 없는 기준가 하락은 모두 `rights`(권리 가치 현금 지급). `restructure`는 **수작업 자본변동 표**에 등록된 경우 공시 비율로 처리하고, 미등록이면 보유 동결 후 재개가 평가 | 계수만으로는 권리락·무상증자·정지 후 재개를 구분할 수 없음(M0: 신라젠 재개 0.6926, 대한항공 권리락 0.7754). 공짜 주식이 생기는 방향의 오분류를 구조적으로 차단 |
| 배당락 | 성과는 가격 수익률. 1차는 추정 배당락 구간 진입 금지 필터만 제공. **평균 보유 기간이 긴 전략은 총수익률 모듈 전까지 P7 등록 차단** | KRX는 1998년 현금배당락 기준가 조정을 폐지. 장기 보유 전략은 배당 누락이 비교를 왜곡하므로 판정 전 게이트 |
| 비용 모델 | 수수료·세금 + 슬리피지. 1층은 회전율 비례 bps, 2층은 참여율 기반 충격 + 참여율 상한 | 슬리피지 누락 시 고회전·소형주 전략 과대평가 |
| 상하한가 체결 | 체결 비율 파라미터 1개(기본 0) + 민감도 분석 | 시가총액 상위 유니버스에서 해당 거래가 드묾 |
| 엔진 | 2층: 벡터화 스크리너 + event-driven 검증기. **신호와 주문 의도(`OrderIntent`)까지 공유**하고 차이는 체결에만 둠 | 주문 정의가 같아야 제약을 끈 층간 일치가 성립 |
| 스누핑 통제 | IS에서 조합 단위 기록과 보수적 DSR. OOS는 **screening holdout**: 사전 등록 기준으로 통과·탈락만 판정, 결과 간 비교 금지, 개봉 총량 한도. OOS 통과를 통계적 검증으로 해석하지 않음 | 여러 판정 중 통과자만 넘기는 것도 선택이므로 다중검정이 남음. 최종 확인은 새 데이터의 전진 검증 |
| 전략 표현 | JSON 스키마 v1, 이벤트형·리밸런싱형 두 계열 | 탐색 범위 확보 |
| 키움 연동 | 별도 프로그램. 전략 패키지 공유, OOS 통과 전략을 파일로 출력해 모의투자 전진 검증 | 백테스트와 실거래의 신호 로직 일치, 최종 선택은 전진 검증 결과로 |
| GUI | PySide6, 상단 바 + 좌측 내비게이션. 키움 프로그램과 같은 디자인 체계. 데이터·결과 화면에 "한국거래소 통계정보" 출처 고정 표시 | 약관 제10조③ |

## 2. 시스템 구성

```
quant-strategy-core  (공유 패키지, 별도 저장소)
   ├─ 전략 스키마 v1, 지표, 신호·목표 비중 생성
   └─ 입력: 가격 DataFrame / 출력: 신호, 목표 비중
        ▲                         ▲
        │ 의존                     │ 의존
krx-backtester              kiwoom-trader
   데이터·엔진·분석·GUI          실시간 데이터·주문·GUI
   └─ 통과 전략 파일 출력 ────────▶ 로드 → 모의투자 전진 검증
```

`quant-strategy-core`는 **데이터 수집, 파일 I/O, GUI, 네트워크에 의존하지 않는다.** 가격 데이터를 받아 신호를 돌려주는 순수 계산 패키지로 유지해야 두 프로그램에서 동일하게 동작한다. 개발 초기에는 `pip install -e ../quant-strategy-core`로 로컬 경로 설치한다.

## 3. 파이프라인

```
[P1 수집] → [P2 정제] → 분석용 DB
                           │
[P3 전략 정의] ────────────┤
                           ▼
                 [P4 1층 스크리너] ── 대량 조합, IS
                           │ 상위 후보
                           ▼
                 [P5 2층 검증기] ── 현실 제약, IS
                           │
                           ▼
                    [P6 분석·비교] ── IS 안에서만 비교·선택
                           │ 후보 확정 + 통과 기준 사전 등록
                           ▼
                 [P7 OOS 판정] ── screening holdout, 통과·탈락만
                           │ 통과 (순위 없음)
                           ▼
                   [P8 전략 파일 출력] → 키움 모의투자

[실험 기록]: P4~P7의 모든 실행을 조합 단위로 자동 기록
```

### P1 수집

| 항목 | 내용 |
|---|---|
| 입력 | KRX 인증키, 수집 기간 |
| 출력 | `raw_daily`, `raw_index`, `instruments`, `collection_log` |
| 모듈 | `data/krx_client.py`, `data/collector.py` |

- 날짜 단위로 KOSPI·KOSDAQ 일별매매정보와 KOSPI 시리즈 지수 일별시세를 호출. 종목기본정보는 매일 호출하지 않고, **새 종목코드가 처음 등장한 날짜에만** 호출
- 조인 키: 종목기본정보 `ISU_SRT_CD`(단축 6자리) ↔ 일별매매정보 `ISU_CD`. 표준코드(12자리)는 `instruments.isu_std_cd`에 보관
- 호출량: 일별매매 2개 + 지수 1개 × 약 4,100거래일 ≈ 12,300회 + 신규 종목 등장일 수. 하루 한도 10,000회이므로 초기 적재는 최소 2~3일
- D일 데이터는 D+1 영업일 08시 이전에 요청하지 않음
- 응답 원문을 가공 없이 저장 (정제 로직이 바뀌어도 재수집 불필요)
- 호출 수를 `collection_log`에 기록, 일일 한도 근접 시 중단 후 다음 실행에서 이어받기
- 빈 응답은 세 가지로 구분해 기록: 휴장일(전 서비스가 빈 응답이고 제공 시점 이후), 미제공(제공 시점 이전), 오류(HTTP 오류·인증 실패). 휴장일만 재호출 대상에서 제외. 실패 호출이 한도에 포함되는지는 확인 대기이므로 포함된다고 가정
- `instruments`의 `first_seen_date`·`last_seen_date`는 **`raw_daily` 최초·최종 등장일**로 산출. 거래정지 종목도 정지 형태 행으로 응답에 포함됨을 M0에서 확인했으므로, `last_seen_date`가 데이터 마지막 날보다 이르면 `delisted_date = last_seen_date`로 둠. 데이터 마지막 날이면 `is_right_censored = true`. 종목기본정보는 종목명·증권구분 보조용
- 초기 전체 적재는 여러 날에 걸쳐 진행됨을 전제로 설계

### P2 정제

| 항목 | 내용 |
|---|---|
| 입력 | 원시 테이블 |
| 출력 | `prices`, `adj_factors`, `price_events`, `market_rules`, 품질 리포트 |
| 모듈 | `data/normalize.py`, `data/adjust.py`, `data/market_rules.py`, `data/quality.py` |

1. **정규화**: 문자열 숫자 변환, 종목코드·날짜 형식 통일. 당일 상장주식수로 당일 시가총액 계산
   - **정지 행 처리**: `시가 = 0` 그리고 `거래량 = 0`이면 `is_halted = true`, 시가·고가·저가는 결측(NULL). 종가는 응답의 직전 값을 유지하되 수익률·지표 계산에는 쓰지 않음
2. **보정 계수 산출**: `(종가 − 대비) / 전일 종가`. `CMPPREVDD_PRC`는 `종가 − 기준가`로 정의된 부호 있는 값(공식 명세, M0 실측 하락 407행 전부 음수). 전일 종가는 **직전 비정지 거래일 종가**. 허용 오차(호가 단위 반올림) 밖이면 이벤트 후보
3. **이벤트 유형 분류**: 이벤트일에 알 수 있는 정보(계수, 직전 거래일 정지 여부, 당일 상장주식수)만으로 아래 순서대로 판정

   | 순서 | 조건 | 분류 | 예시 (M0) |
   |---|---|---|---|
   | ① | 직전 거래일이 정지, `1/계수`가 분할·병합 비율(2, 5, 10, 50, 1/5 등)에 근접, 상장주식수 변화율이 `1/계수`와 일치 | `share_change` | 삼성전자 2018 액면분할 |
   | ② | 직전 거래일이 정지, ①에 해당하지 않음 | `restructure` | SK텔레콤 2021 분할+인적분할(계수 0.1725), 신라젠 재개(0.6926, 정지 중 주식수 1.437배) |
   | ③ | 직전 거래일이 정지 아님, 계수 < 1 | `rights` | 대한항공 유상증자(0.7754), 무상증자도 여기로 분류 |
   | ④ | 그 외 (정지 없이 계수 > 1 등) | `unverified` | |

   - ①은 **분할 비율과 주식수 변화가 둘 다** 맞아야 함. 신라젠처럼 주식수 변화율(1.437)이 우연히 `1/계수`(1.444)에 가까워도 분할 비율이 아니면 ②로 감
   - ③에 무상증자가 섞이는 것은 의도된 선택. 권리 가치 현금 지급으로 가치는 보존되고 익스포저만 작아지는 방향이며, 공짜 주식이 생기는 반대 방향 오분류를 막음
   - `rights`의 주당 권리 가치는 **응답에서 역산한 기준가**로 계산(`전일 종가 − 기준가`). 공시 발행가액 기반 이론 기준가와의 차이(대한항공 +0.23%)는 품질 리포트에만 기록
   - 사후 검증: 이후 상장주식수 변화로 분류를 확인하되, **정지 구간 중의 상장주식수 변화는 별도 항목으로 분리**해 품질 리포트에 기록하고 엔진 처리에 소급하지 않음
4. **정지 후 재개와 수작업 자본변동 표**
   - `restructure`는 보정 계수를 적용하지 않음. 정지 전후 가격 차이는 실제 손익으로 반영
   - **수작업 자본변동 표** `config/corporate_actions.csv`: 인적분할·분할합병 등 `restructure` 중 실제 자본변동인 건을 DART 공시에서 확인해 등록. 컬럼은 종목코드, 정지 시작일, 재개일, 유형, 존속 법인 주당 신주 수, 신설 법인 코드와 주당 배정 주식 수, 공시일, 공시 URL
   - 등록 건은 `known_date = 공시일`(재개일보다 앞섬)로 두고 재개일에 공시 비율로 처리. 미등록 건은 `known_date = 재개일`, 보유 동결 후 재개가 평가
   - 품질 리포트는 유니버스 후보(시가총액 상위 N) 안의 `restructure` 전체를 목록으로 출력. 각 건을 표에 등록하거나 "자본변동 아님(재개 리셋)"으로 표시해야 M2 완료
   - 신규상장·재상장은 시계열 시작점으로 처리

   **인과성 원칙**: 모든 이벤트에 `known_date`를 기록하고, 엔진은 `known_date ≤ 해당 거래일`인 이벤트만 행동 근거로 사용
5. **누적 보정 가격 생성**: 계수를 역방향 누적해 두 계열을 만들고 원시 가격도 보관
   - **지표용 `adj_*`**: `share_change`와 `rights` 계수를 모두 반영. 권리락일 가짜 하락 신호 방지
   - **수익률용 `ret_*`**: `share_change` 계수만 반영. `rights`·`unverified`는 반영하지 않아 원시 가격 경로를 따름. 1층 수익률은 이 계열로 계산해 2층의 주식 수 처리와 일치시킴
6. **거래 상태 표시**: 거래정지일, 상장폐지일, 20일 유효 거래일 수, 관리종목 여부
   - 관리종목 원천: 코스닥은 `SECT_TP_NM = '관리종목(소속부없음)'`(M0: 신라젠 공식 지정·해제일 당일 값 변화 확인). **유가증권은 응답으로 판별 불가**(관리종목도 빈 문자열)이므로 `is_managed = NULL`
7. **추정 배당락 구간**: 결산월 규칙으로 추정 배당락일 산출해 `ex_div_estimates`에 저장 (진입 금지 필터 전용, 가격 보정에는 사용 안 함)
8. **제도 테이블**: 날짜 구간별 가격제한폭, 거래세율, 기본 수수료, **호가 단위 구간표**(`tick_rules`: 시장별 × 2023-01-25 개편 전후, `price_from ≤ 가격 < price_to`). 상한가·하한가 가격은 `기준가 × (1 ± 가격제한폭)`을 호가 단위로 내림·올림해 계산(응답에 상하한가 필드 없음). 구간 경계값과 2010~2023 사이 다른 변경 여부는 공식 조문 확인 후 확정
   - **가격제한폭 비적용일**: 신규상장일, 정리매매 기간처럼 제한폭이 적용되지 않는 날은 응답으로 식별할 수 없음. 등락률 절댓값이 해당 날짜 제한폭을 넘는 행은 **제한폭 비적용일로 표시**하고, 그날은 상하한가 판정을 하지 않음
9. **교차검증**: 수정주가 제공 라이브러리와 비교. 괴리율이 허용 기준을 넘는 건이 원인 미설명 상태로 남아 있으면 M2 완료 불가
10. **품질 검사**: 누락 날짜, 가격 0(정지 행 제외), 호가 단위 배수 위반 건수, 제한폭 초과 행(스냅샷에서 사라지기 직전 구간은 정리매매 추정으로 별도 집계), `unverified`·`restructure` 건수, 정지 구간 상장주식수 변화 건수
   - 호가 단위 배수 위반 0건은 구간표를 같은 데이터에서 역산한 경우 **독립 검증이 아님**. 구간표는 공식 조문으로 확정한 뒤 이 검사를 적용
11. **구조 변경 사례 대조**: SK텔레콤 2021(분할+인적분할), 신라젠(정지 후 재개 리셋), 삼성전자 2018(정지 후 분할)이 각각 ②·②·①로 판정되는지 확인

### P3 전략 정의

| 항목 | 내용 |
|---|---|
| 입력 | GUI 입력 또는 JSON 파일 |
| 출력 | 검증된 전략 객체, 전략 해시 |
| 모듈 | `quant-strategy-core`: `schema.py`, `indicators.py`, `event_strategy.py`, `rebalance_strategy.py` |

두 계열을 같은 인터페이스로 다룬다. 모든 전략은 최종적으로 **날짜×종목 목표 비중 행렬**을 만들 수 있어야 한다.

| 요소 | 이벤트형 | 리밸런싱형 |
|---|---|---|
| 공통 | 유니버스 필터, 지표 정의, 파라미터 범위, 배당락 구간 필터 | 동일 |
| 매수 결정 | 진입 조건 (AND) + 후보 정렬 | 점수식 + 상위 N 선택 |
| 매도 결정 | 청산 조건 (OR): 신호, 손절, 익절, 시간, 트레일링 | 다음 리밸런싱에서 탈락 |
| 주기 | 매 거래일 | 월말, 분기말 등 |
| 비중 | 균등, 고정 비중, 고정 리스크 | 균등, 점수 비례, 역변동성 |
| 제약 | 최대 보유 수, 재진입 대기일 | 최대 보유 수, 종목당 비중 상한 |

- 지표 입력 가격: `adj_close`(기본) 또는 원시 `close`
- **지표는 정지 행을 제외한 거래일 시계열로 계산**. 정지 기간의 반복 종가로 RSI·이동평균·변동성이 왜곡되지 않게 함
- 전략 해시: 스키마 전체(파라미터 값 포함)의 정규화 JSON 해시. 실행 식별용
- **비중의 의미**: 목표 비중은 매매가 일어나는 시점에만 적용된다. 이벤트형은 진입 시점, 리밸런싱형은 리밸런싱일. 그 사이 보유 비중은 가격 변동에 따라 표류하며, 매일 목표 비중으로 되돌리지 않는다

스키마 검증 규칙 (실행 전 차단):
- 고정 리스크 사이징인데 손절 없음
- 이벤트형인데 청산 조건 없음
- 지표 참조 이름이 정의되지 않음
- 파라미터 조합 수가 설정 상한 초과
- `exclude: ["managed"]`인데 유니버스 시장에 유가증권이 포함됨 (관리종목 판별 불가)

### P4 1층 스크리너

| 항목 | 내용 |
|---|---|
| 목적 | 수백~수천 조합을 빠르게 걸러내기 |
| 입력 | 전략 + 파라미터 범위, IS 데이터 |
| 출력 | 조합별 요약 지표·일별 수익률, 상위 후보 목록 |
| 모듈 | `engine/screener.py`, `engine/parallel.py` |

계산 방식 (날짜 방향 루프, 종목 방향 벡터 연산):
- 신호 확정은 t일 종가, 체결은 t+1일 시가
- 구간 정의: 구간 k는 k일 시가 체결 직후부터 k+1일 시가 직전까지. 구간 시작 비중 `h_i[k]`, 구간 수익률 `r_i[k]` = k일 `ret_open` → k+1일 `ret_open`. **수익률용 보정 시가**를 사용해 분할일 가짜 수익률 방지
- 포트폴리오 구간 수익률 `R[k] = Σ h_i[k] × r_i[k]` (현금 수익률 0)
- 다음 구간 시작 전 표류 비중 `d_i[k+1] = h_i[k] × (1 + r_i[k]) / (1 + R[k])`
- **주문**: t일 종가에 공통 모듈이 만든 `OrderIntent`(매도 `sell_fraction`, 매수 `target_notional = t일 종가 NAV × 목표 비중`)를 2층과 동일하게 소비
- **현금 비중** `c`를 명시적으로 추적하고 항상 `Σ h_i + c = 1`, `h_i ≥ 0`, `c ≥ 0`
- k+1일 매매 순서: 매도 의도로 `h_i`를 줄여 `c`에 가산 → 매수 의도의 비중 `target_notional ÷ (k+1일 시가 기준 NAV)`를 계산 → 매수 비중 합(비용 포함)이 `c`를 넘으면 매수 의도를 비례 축소 → 매수 반영. 매매 없는 종목은 표류 비중 유지
- `rights` 이벤트일(장전): 해당 종목 표류 비중에 `(전일 종가 − 기준가) / 당일 시가`를 곱한 만큼 현금 비중에 가산한 뒤 전체를 재정규화. 2층의 `보유 주식 수 × 주당 권리 가치` 현금 지급과 금액이 같음
- 매매량 `Δ_i = h_i[k+1] − d_i[k+1]` (표류 비중 대비 실제 매매량, 목표 비중 변화가 아님)
- 비용률 `C[k+1] = Σ max(Δ_i, 0) × (수수료율 + 슬리피지 bps) + Σ max(−Δ_i, 0) × (수수료율 + 거래세율 + 슬리피지 bps)`. **거래세는 매도에만** 부과. 세율은 제도 테이블에서 날짜별 조회
- **순수익률**: 비용은 k+1일 시가 매매 시점 자산에서 현금으로 지급하고, 매매 후 비중은 비용 차감 후 자산 기준으로 정규화
  `R_net[k+1] = (1 − C[k+1]) × (1 + R[k+1]) − 1`
- 스크리너의 모든 성과 지표와 `trial_returns`는 `R_net` 기준. 비용 차감 전 `R`은 손익분기 비용 계산용으로만 함께 저장
- 상장폐지: 보유 종목이 스냅샷에서 사라진 다음 날 인식하고, 직전 거래일 종가로 청산. 마지막 구간 수익률은 `ret_open` → 최종 거래일 `ret_close`로 계산하고 비중을 현금으로 전환. 2층과 동일
- 거래정지: 정지 구간 수익률 0, 보유 동결. 재개일 구간에는 **정지 직전 거래일 `ret_open` → 재개일 `ret_open`** 수익률을 반영
- `restructure` 재개일: 수작업 표 등록 건은 존속 법인 보유분에 공시 주식 비율을 적용하고 신설 법인 비중을 추가(2층과 같은 금액). 미등록 건은 원시 가격 경로 그대로
- 결측 수익률을 0으로 채우는 처리는 금지 (거래정지의 명시적 0과 구분)
- 유효 거래일 20일 미만 종목과 `unverified` 이벤트가 발생한 종목(`known_date` 이후)은 신규 진입 대상에서 제외 (2층과 동일)
- 조합마다 요약 지표와 일별 수익률 시계열을 실험 기록에 저장

근사로 무시하는 것: 상하한가 체결 제약, 거래정지 중 주문 이월(1층은 정지 종목 주문을 취소), 정수 주, 참여율에 따른 충격 증가(고정 bps로 근사). 조합 단위로 `multiprocessing` 병렬 처리.

### P5 2층 검증기

| 항목 | 내용 |
|---|---|
| 목적 | 상위 후보를 실제 매매에 가깝게 재현 |
| 입력 | 1층 상위 후보, IS 데이터, 초기 자본, 비용·체결 설정 |
| 출력 | 일별 자산 곡선(시가 스냅샷, 종가 스냅샷), 거래 로그, 미체결 로그 |
| 모듈 | `engine/validator.py`, `engine/execution.py`, `engine/portfolio.py`, `engine/sizing.py` |

1층과 같은 신호 코드와 `OrderIntent` 생성 함수를 호출하고, 차이는 체결 모델에만 둔다.

일별 루프: 반복 한 번은 **거래일 d 하루**이며, 세 단계를 이 순서로만 실행한다.

**① 장전 (d일 시가 이전)**
1. 잔고 재조정: d일에 `adj_factors` 이벤트가 있는 보유 종목
   - `share_change`(분할·무상증자·병합): 보유 주식 수 × (1 / 계수), 평균 매입 단가 × 계수
   - `rights`(유상증자 권리락): **주식 수와 평균 매입 단가는 유지**하고 `보유 주식 수 × 주당 권리 가치`를 현금으로 지급. 청약·신주 상장은 모델링하지 않음(권리 현금화 근사), 거래 로그에 표시
   - `unverified`: **주식 수를 재조정하지 않고** 경고 기록. 해당 종목은 이후 신규 진입 대상에서 제외
2. 대기 주문 확인: 대기 주문은 `OrderIntent`로 저장되므로 계수 조정이 필요 없음
   - 매도 `sell_fraction`(전량 = 1.0)은 재조정된 잔고에 그대로 적용
   - 매수 `target_notional`은 금액이므로 이벤트와 무관
3. 거래정지·구조 변경: 정지 중인 보유 종목은 동결하고 직전 비정지 거래일 종가로 평가. 재개일에 `restructure`이면
   - 수작업 표 등록 건: 존속 법인 주식 수 × 공시 주당 신주 수, 신설 법인 주식을 공시 배정 비율로 추가(신설 법인 첫 거래일부터 일반 보유 종목으로 취급). 평균 매입 단가는 재개 직전 평가액을 존속·신설 법인 재개일 가격 비율로 배분
   - 미등록 건: 주식 수 유지, 재개일 가격으로 평가, 거래 로그에 "구조 변경 재개(미등록)" 표시
   - 어느 경우도 정지 전에 청산하지 않음

**② 시가 (d일 시가)**
4. 대기 주문 체결 (d−1일 종가에 생성된 주문). 아래 순서로 한 번에 처리하며, 슬리피지·수수료·거래세는 각 체결 시점에 즉시 확정
   1. 거래정지 종목 주문은 이월
   2. 매도 체결: 하한가 시가면 상하한가 체결 비율만큼만 체결하고 잔량 이월. 순대금(체결 대금 − 슬리피지 − 수수료 − 거래세)을 현금에 반영
   3. 매수 수량 산출: `목표 금액 ÷ (d일 원시 시가 × (1 + 수수료율 + 예상 슬리피지율))`, 정수 주 내림. 예상 슬리피지율은 목표 금액 기준 참여율로 계산. 상한가 시가면 상하한가 체결 비율 적용
   4. 매수 총지출(체결 대금 + 슬리피지 + 수수료)이 가용 현금을 넘으면 목표 금액을 비례 축소해 3을 재계산하고, 그래도 넘으면 1주씩 감소
   5. 매수 체결 후 현금 반영
   - 상하한가 판정은 제도 테이블로 계산한 상하한가 가격(또는 M0에서 확인된 원시 필드)과 비교
5. **현금 검사**: 모든 비용 확정 후 현금 < 0 이면 실행 중단하고 오류 기록 (가짜 레버리지 방지)
6. **시가 스냅샷 기록**: 현금 + Σ(보유 주식 수 × d일 원시 시가)

**③ 종가 (d일 종가)**
7. 보유 종목이 d일 스냅샷에서 사라졌고 거래정지로 설명되지 않으면(`known_date = d`), 직전 거래일 원시 종가로 청산 처리. 그날이 마지막 날임을 미리 알 필요 없이 같은 가격에 인식
8. **종가 스냅샷 기록**: 현금 + Σ(보유 주식 수 × d일 원시 종가)
9. d일 유니버스 필터 (해당 시점 기준)
10. `quant-strategy-core`로 신호·목표 비중 계산
11. 청산 우선순위 적용 (같은 날 겹치면 설정된 규칙)
12. 공통 모듈로 `OrderIntent` 생성(1층과 동일): 매수는 `target_notional`(종가 스냅샷 × 목표 비중), 매도는 `sell_fraction`

두 스냅샷의 용도:
- 시가 스냅샷: 1층 스크리너와의 대조 (M5)
- 종가 스냅샷: 성과 지표, MDD, 벤치마크 비교, 화면 표시

슬리피지 모델 (`engine/execution.py`):
- 참여율 `p = 주문금액 / ADV20`. `ADV20`은 t일까지의 20일 평균 거래대금 (체결일 거래량은 시가 시점에 알 수 없으므로 사용 금지)
- 체결가 불이익 = `기본 bps + 충격 계수 × √p`, 매수는 불리하게 올리고 매도는 내림
- `p`가 참여율 상한을 넘으면 상한까지만 체결하고 잔량은 미체결로 기록
- 유효 거래일 20일 미만인 보유 종목의 청산은 **최대 슬리피지 bps 고정** 적용 (0으로 나누기 방지)
- 기본 bps, 충격 계수, 참여율 상한, 최대 bps는 `config/default.toml`에서 설정. 초기값은 가정이므로 P6 민감도 분석 대상
- 슬리피지 적용 후 가격을 호가 단위로 강제 올림·내림하지 않음. 시가 단일가매매는 스프레드를 건너지 않으므로 1호가 최소 비용을 부과하면 비용이 과대평가됨. 장중 체결 모델을 도입할 때 재검토

### P6 분석·비교

| 항목 | 내용 |
|---|---|
| 모듈 | `analysis/metrics.py`, `analysis/compare.py`, `analysis/deflated_sharpe.py` |

**모든 비교와 선택은 IS 결과로만 한다.**

- 기본 지표: CAGR, MDD, Sharpe, Sortino, 승률, 손익비, 회전율, 평균 보유일
- 벤치마크 대비 성과 (가격지수 기준, 화면에 "가격 수익률" 명시)
- **Conservative DSR (raw trial count)**: Bailey & López de Prado (2014)의 DSR에 시도 수로 원시 조합 수를 넣은 보수적 근사. 입력은 원시 시도 수, 전 조합 Sharpe 분산, 선택 전략의 왜도·첨도·표본 길이. 인접 조합의 상관 때문에 독립 시도 수보다 과하게 할인됨을 화면에 표시
- 층간 괴리: 1층 대비 2층 성과 차이. 괴리가 큰 전략은 실행 가정에 민감한 것으로 표시
- 민감도 분석: 슬리피지 배수, 상하한가 체결 비율(0, 0.5, 1)과 영향 거래 수
- 손익분기 비용: `비용 차감 전 초과수익 ÷ 연간 회전율`로 계산해, 성과가 0이 되는 비용 수준을 재실행 없이 표시
- 구조 변경 보유 동결·권리 현금 지급·`unverified` 제외가 영향을 준 거래 수 표시
- 파라미터 안정성: 인접 파라미터 조합의 성과 분포 (한 점만 좋은 조합 경고)
- 구간별 성과: 연도별, 상승·하락장별

### P7 OOS 판정 (screening holdout)

| 항목 | 내용 |
|---|---|
| 모듈 | `research/oos_guard.py` |

OOS는 전략을 **고르는 곳이 아니라 통과·탈락을 판정하는 곳**이다. 단, 여러 전략을 판정해 통과자만 넘기는 것도 선택이므로 다중검정 문제가 남는다. 따라서 이 단계는 **통계적 확인이 아니라 선별용 holdout**으로 정의하고, OOS 통과를 검증 완료로 해석하지 않는다. 최종 확인은 판정 이후 새로 발생한 데이터의 키움 모의투자 전진 검증이 담당한다.

봉인:
- `oos_windows`에 OOS 구간과 개봉 총량 한도를 등록
- 활성 OOS 구간의 데이터는 데이터 접근 계층에서 반환 차단

구간 경계 처리 (IS·OOS 공통):
- 지표 워밍업: 실행 구간 시작 전 데이터를 지표 계산에만 사용 (예: 200일 이동평균). OOS 실행은 IS 데이터를 워밍업으로 읽을 수 있고, IS 실행은 OOS 데이터를 읽을 수 없음
- 포지션: 실행 구간 첫날 현금 100%로 시작. 구간 시작 전 신호로 생긴 포지션을 이월하지 않음
- 성과·거래 수: 실행 구간 첫날부터만 집계. 데이터 시작일(2010년) 직후 워밍업 기간도 IS 성과에서 제외

판정 절차:
1. IS에서 후보 전략 확정 (전략 해시 기록). **IS 2층 거래 로그의 평균 보유 기간이 설정 임계값(기본 20거래일)을 넘는 전략은 총수익률 모듈(11장) 도입 전까지 등록 불가**
2. 개봉 전에 `oos_registrations`에 등록
   - 통과 기준 (예: Sharpe 하한, MDD 상한, 최소 거래 수)
   - 기준 비용·체결 설정 1개
   - 스트레스 설정 목록 (예: 슬리피지 2배·3배, 상하한가 체결 비율 0과 1)
3. 2층 검증기로 기준 설정과 스트레스 설정을 **한 번의 개봉에서 모두 실행**. 예산은 1회만 소모
4. **기준 설정 결과로만** 통과·탈락 판정. 스트레스 결과와 손익분기 비용은 기록·표시용이며 판정을 바꾸지 않음

금지 사항:
- 등록 후 기준·설정 목록 수정 불가
- 같은 전략 해시 재판정 불가. 비용·체결 설정만 바꾼 사후 재실행도 허용하지 않음 (탈락 전략을 유리한 설정으로 통과시키는 경로 차단)
- GUI에 OOS 결과끼리 정렬·비교하는 화면을 두지 않음. 통과 전략은 순위 없이 모두 P8로 전달
- 결과 화면과 출력 파일에 해당 OOS 구간의 **판정 수 대비 통과 수**를 항상 함께 표시

총량 한도:
- 모든 판정(파라미터만 바꾼 재시도 포함)이 한도를 소모
- 한도를 모두 쓰면 구간은 `consumed`로 전환되어 이후 IS로 취급
- 새 OOS 구간은 시간이 지나 새로 쌓인 데이터로만 등록

최종 선택은 키움 모의투자 전진 검증 결과로 한다.

## 6. 불변 규칙

코드 리뷰와 테스트로 강제한다.

1. t일 신호는 t일 종가까지의 데이터만 사용하고, 체결은 t+1일 이후
2. 유니버스 필터는 매 거래일 해당 시점의 데이터로 계산. 시가총액은 당일 상장주식수 기준이며, 상장폐지 종목은 폐지 직전 거래일까지 포함
3. 지표 계산은 지표용 보정 가격(`adj_*`), 1층 수익률은 수익률용 보정 가격(`ret_*`, 분할만 반영), 2층 체결·가격제한폭 판단·평가는 원시 가격
4. 2층 일별 루프는 장전 → 시가 → 종가 순서로만 실행. 자본변동 처리(잔고 재조정, 권리 현금 지급)는 장전 단계에서 다른 모든 처리보다 먼저 실행
5. 대기 주문은 수량으로 저장하지 않음. 매도는 보유 대비 비율, 매수는 목표 금액으로 저장
6. 2층 현금은 어느 시점에도 음수가 될 수 없음. 매수 수량은 비용을 선반영해 산출하고, 매도를 먼저 체결
7. 모든 성과는 비용 차감 후 순수익률 기준. 거래세는 매도에만 부과 (1층, 2층 공통)
8. 목표 비중은 매매 시점에만 적용하고, 보유 중 비중은 표류시킴 (1층, 2층 공통)
9. 성과는 가격 수익률로 계산하고 결과에 명시
10. 유효 거래일 20일 미만 종목과 `unverified` 이벤트 종목은 신규 진입 불가 (1층, 2층 공통)
11. 체결 모델이 참조하는 거래량·거래대금은 체결 시점 이전 데이터만 사용
12. 보유 종목의 결측 수익률을 0으로 채우지 않음. 상장폐지는 스냅샷에서 사라진 날 인식해 직전 거래일 종가로 청산(1층·2층 동일), 거래정지(`restructure` 포함)는 보유 동결 후 재개 가격으로 평가
13. 분류되지 않은 가격 이벤트(`unverified`)로 보유 주식 수를 바꾸지 않음. `rights`는 주식 수를 늘리지 않고 권리 가치를 현금으로 지급
14. 엔진은 `known_date ≤ 거래일`인 이벤트만 행동 근거로 사용. 사후 분류·검증 결과를 과거 주문에 소급하지 않음
15. 1층과 2층은 같은 `OrderIntent`를 소비하며, 1층도 `Σ 비중 + 현금 = 1`, 현금 ≥ 0을 지킴
16. 활성 OOS 구간 데이터는 `oos_guard`를 거치지 않고 접근 불가. 실행 구간 이전 데이터는 지표 워밍업에만 쓰고, 포지션은 구간 첫날 현금으로 시작
17. 상장·상장폐지일은 일별 스냅샷 등장 기록으로 산출
18. OOS 결과는 통과·탈락 판정에만 사용하고 전략 간 비교·선택에 사용하지 않음. 판정은 사전 등록한 기준 설정 결과로만 함
19. `quant-strategy-core`는 I/O, 네트워크, GUI에 의존하지 않음
20. 1층과 2층은 같은 신호 함수와 같은 `OrderIntent` 생성 함수를 호출
21. 모든 백테스트 실행은 조합 단위로 실험 기록에 남음
22. API 키는 저장소 밖(`keyring`)에 저장
23. 정지 행(시가 0, 거래량 0)의 가격은 수익률·지표·체결에 쓰지 않음
24. 이벤트 분류는 직전 거래일 정지 여부를 먼저 판정. 정지 없는 기준가 하락으로 주식 수를 늘리지 않음
25. KRX 응답 원문과 그 값을 담은 fixture는 저장소에 넣지 않음. fixture는 사례 구조를 본뜬 가짜 값으로만 작성(약관 제11조②)

## 11. 2차 확장 후보

1차에서 제외했지만, 아래 조건이 관측되면 도입한다.

| 항목 | 내용 | 도입 조건 |
|---|---|---|
